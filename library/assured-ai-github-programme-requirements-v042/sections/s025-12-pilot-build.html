12. Pilot build

Before any bulk import, the agent builds and tests this small set. Use representative Assured AI work items that reflect genuine planned activities, each clearly marked as a pilot. Do not create artificial dependencies between unrelated technical tasks, and do not move or change existing operational work (for example the project 110 items) to test the configuration. After the pilot passes, the project 110 items are reviewed with Ritika and agreed work is brought into the right repositories; where technical work stays in an external repository, the WHO coordination issue links to it.

  • 1 epic in aai-programme
  • 2 features in two different workstream repositories, as sub-issues of the epic
  • 1 native "blocked by" relationship between the two features
  • 1 D-number issue in aai-programme
  • 1 decision issue in aai-programme
  • 1 research question issue
  • 1 milestone issue
  • 1 restricted note in aai-pm, linked from the pilot epic
  • 1 item with Review type set
  • 1 item labelled thin-slice
  • 1 item labelled sprint-demo
  • 1 workstream issue linking to an external partner repository (BD-02a)

The pilot must prove each of these:

IDTest
PIL-01An organisation issue field changed on a thin-slice workstream item shows the same value in its workstream project and the programme project
PIL-02Sub-issue progress from two repositories rolls up into the epic in V1
PIL-03The test partner account cannot open the aai-pm note or see its content from the link on the pilot epic
PIL-04No aai-pm issue appears in the programme project
PIL-05A blocked label on a feature sets Delivery health to Blocked on the epic within one run of the Action, and the epic appears in V10
PIL-06Every view in section 8.1 returns the right pilot items
PIL-07The test partner account sets Integration readiness to Validated on a pilot item with no confirmation comment. AUTO-10 adds the validation-exception label and one comment. Running it again adds nothing more. When the Technical Integration Lead adds the confirmation comment, the label is removed
PIL-08Closing a pilot epic as completed sets Programme status to Done through AUTO-03
PIL-09Closing a pilot item as not planned sets Programme status to Cancelled, and reopening it sets In progress
PIL-10The pinned fields in section 5.3 appear on the issue form for each pilot issue type
PIL-11Charts M1 to M5 show the pilot items correctly, or the report records which cannot be built natively

If any test fails, stop and report. Delete or close the pilot items once the bulk import is complete.
